# EDM Architectural Specification: v0.0.12 Hotfix
**Document ID**: SPEC-2026-HOTFIX-v0.0.12  
**Version**: 1.1.0 (EGM Post-Review Approved)  
**Status**: APPROVED FOR SURGICAL EXECUTION  
**Scope**: `packages/engine`, `apps/desktop`, `Cargo.toml`, Version Bump  

---

## 1. Specification Objectives & Invariants

This specification resolves two critical download execution bugs identified in v0.0.11:
1. BitTorrent `.torrent` re-downloads and local file ingestion stalling at 0 B/s due to unhandled `overwrite: false` and missing error state handling.
2. YouTube download initial failures, `"watch.mp4"` collision, 10M chunk buffering stalls, and re-download failures.

### 1.1 Invariants
- **INV-BT-08 (Unconditional Overwrite & Resume Support)**: BitTorrent sessions must set `AddTorrentOptions { overwrite: true, ..Default::default() }`. If local files already exist, the engine verifies existing piece hashes and resumes or seeds rather than failing.
- **INV-BT-09 (Fail-Fast Swarm Error Interception)**: If `stats.state == librqbit::TorrentStatsState::Error`, the engine must break immediately and report `BitTorrent task entered error state`, preventing 0-bps infinite loops.
- **INV-BT-10 (Tier-1 Tracker URL Enrichment)**: When adding a `magnet:` link, enrich the URI query with active Tier-1 public trackers (`&tr=...`) before passing to `AddTorrent::from_url`.
- **INV-BT-11 (Verification Phase Telemetry)**: When `librqbit` is in `TorrentStatsState::Initializing`, the engine must emit `phase: Some("Verifying")` and `decision_reason: "Verifying existing pieces on disk..."`. The UI must refresh `smooth.lastProgressTime` during this phase so the 10-second stall watchdog is not triggered.
- **INV-BT-12 (Multi-file Recursive Payload Resolution)**: When a torrent is multi-file, recursively inspect `target_file_path` to find the largest payload file regardless of nested directory depth.
- **INV-YT-01 (Clean Client Negotiation)**: yt-dlp must not be forced into deprecated/gated clients like `ios` without PO-Tokens. Remove `--extractor-args "youtube:player_client=ios,web,default"`. Default client resolution with Node.js challenge solving must be used.
- **INV-YT-02 (Granular Progress Streaming)**: Remove `--http-chunk-size 10M` to allow smooth, real-time progress updates and avoid false 10-second stalled trips.
- **INV-YT-03 (Collision-Free Dynamic Templating)**: Tasks with generic filenames (`"watch"`, `"watch.mp4"`, `"video"`, `"video.mp4"`, `"download"`, `"download.bin"`, `"media"`, `"media.mp4"`, or empty) must resolve to `"%(title)s.%(ext)s"`.
- **INV-YT-04 (Force Overwrite on Explicit Execution)**: yt-dlp must be passed `--force-overwrites` so retries and duplicate confirmations overwrite cleanly.
- **INV-YT-05 (Detection of Pre-Existing Target)**: If yt-dlp outputs `[download] <path> has already been downloaded`, normalize `<path>` against `task.save_dir` if relative, assign to `final_path`, and immediately emit completed 100% telemetry.
- **INV-YT-06 (Fallback Context Coherence)**: When falling back to `YouTubeExtractor` (`ANDROID_VR`), the stream download task must inherit the Android VR User-Agent and use bounded connection concurrency (1-2) to avoid CDN 403 blocks.
- **INV-VER-12 (Monorepo v0.0.12 Alignment)**: All crate manifests, frontend packages, changelogs, and bug logs must increment from `0.0.11` to `0.0.12`.

   ```rust
   fn find_largest_file_recursive(dir: &std::path::Path) -> Option<std::path::PathBuf> {
       let mut best_file = None;
       let mut max_size = 0u64;
       let mut stack = vec![dir.to_path_buf()];
       while let Some(current) = stack.pop() {
           if let Ok(entries) = std::fs::read_dir(&current) {
               for entry in entries.flatten() {
                   let path = entry.path();
                   if path.is_dir() {
                       stack.push(path);
                   } else if path.is_file() {
                       let sz = std::fs::metadata(&path).map(|m| m.len()).unwrap_or(0);
                       if sz > max_size {
                           max_size = sz;
                           best_file = Some(path);
                       }
                   }
               }
           }
       }
       best_file
   }
   ```

#### `packages/engine/src/packs/ytdlp.rs`
1. Dynamic template matching:
   ```rust
   let is_generic = task.filename.trim().is_empty()
       || task.filename == "download"
       || task.filename == "download.bin"
       || task.filename == "watch"
       || task.filename == "watch.mp4"
       || task.filename == "video"
       || task.filename == "video.mp4"
       || task.filename == "media"
       || task.filename == "media.mp4";
   let target_name = if !is_generic {
       let sanitized = crate::sanitizer::Sanitizer::sanitize_filename(&task.filename);
       let safe_name = sanitized.replace('%', "%%");
       let ext = safe_name.rsplit('.').next().unwrap_or("mp4");
       if ext == "mp4" || ext == "mkv" || ext == "webm" || ext == "mp3" || ext == "m4a" {
           format!("{}.%(ext)s", safe_name.trim_end_matches(&format!(".{}", ext)))
       } else {
           format!("{}.%(ext)s", safe_name)
       }
   } else {
       "%(title)s.%(ext)s".to_string()
   };
   ```
2. Spawn yt-dlp with `--force-overwrites`, without `--extractor-args "youtube:player_client=ios,web,default"` and without `--http-chunk-size 10M`.
3. Associate process with job object:
   ```rust
   super::process::assign_child_to_job(&child);
   ```
4. Normalize `[download] <path> has already been downloaded`:
   ```rust
   } else if line.contains("has already been downloaded") {
       let path_str = line
           .trim_start_matches("[download]")
           .trim()
           .trim_end_matches("has already been downloaded")
           .trim();
       if !path_str.is_empty() {
           let p = PathBuf::from(path_str);
           let abs_p = if p.is_absolute() { p } else { task.save_dir.join(p) };
           final_path = Some(abs_p);
       }
   }
   ```
5. Robust fallback file discovery:
   If `final_path.is_none()`, scan `task.save_dir` for the newest modified file not ending in `.part` or `.ytdl`.
